# 日志/异常/错误处理架构规范

> 本 skill 供架构师设计架构方案时参考，也可供开发编码时查阅。

---

## 1. 错误码体系

### 分层编码规则

架构方案必须定义统一的错误码格式：`{模块}_{编号}`

| 模块前缀 | 说明 | 示例 |
|---------|------|------|
| `AUTH` | 认证相关 | `AUTH_001`（Token过期） |
| `PERM` | 权限相关 | `PERM_001`（无权限） |
| `USER` | 用户管理 | `USER_001`（用户不存在） |
| `SYS` | 系统级 | `SYS_001`（参数校验失败） |

### HTTP 状态码映射

| HTTP 码 | 场景 | 业务码范围 |
|---------|------|----------|
| 400 | 参数校验失败 | `SYS_001` ~ `SYS_099` |
| 401 | 未认证 | `AUTH_001` ~ `AUTH_099` |
| 403 | 已认证但无权限 | `PERM_001` ~ `PERM_099` |
| 404 | 资源不存在 | 各模块 `*_001` |
| 409 | 业务冲突 | 各模块 `*_002` ~ `*_099` |
| 500 | 系统内部错误 | `SYS_100`+ |

### 错误响应格式

```json
{
  "code": "AUTH_001",
  "message": "Token已过期，请重新登录",
  "detail": null,
  "timestamp": "2026-05-11T10:30:00Z",
  "traceId": "abc-123-def"
}
```

## 2. 异常传播策略

### 各层职责

| 层 | 异常处理 |
|---|---------|
| Controller | **不捕获**，交给全局异常处理器 |
| Service | 捕获业务异常转为业务错误码，不捕获系统异常 |
| Repository | **不捕获**，让数据库异常冒泡到 Service |
| 外部调用 | **必须捕获**，转为业务异常或降级 |

### 全局异常处理器

```
GlobalExceptionHandler
  ├─ catch BusinessException → 业务错误码 + message
  ├─ catch ValidationException → 400 + 字段错误列表
  ├─ catch AccessDeniedException → 403
  ├─ catch Exception → 500 + traceId
```

## 3. 日志规范

### 结构化日志字段

| 字段 | 说明 | 示例 |
|------|------|------|
| `timestamp` | 时间戳 | `2026-05-11T10:30:00.123Z` |
| `level` | 日志级别 | `INFO` / `WARN` / `ERROR` |
| `traceId` | 请求链路ID | `abc-123-def` |
| `userId` | 操作人 | `user_123` |
| `action` | 操作 | `login` / `create_project` |
| `module` | 模块 | `auth` / `user` |
| `message` | 描述 | `用户登录成功` |

### 日志级别使用场景

| 级别 | 何时用 | 示例 |
|------|--------|------|
| `DEBUG` | 开发调试信息 | SQL 参数、缓存命中 |
| `INFO` | 业务关键节点 | 用户登录、订单创建 |
| `WARN` | 可恢复的异常 | 第一次重试成功、降级触发 |
| `ERROR` | 需要人工介入 | 重试失败、数据不一致 |

## 4. 敏感数据脱敏

| 字段类型 | 脱敏方式 | 示例 |
|---------|---------|------|
| 密码 | 不记录 | 日志中完全不出现 |
| Token | 截断 | `eyJhb...xxx` |
| 手机号 | 中间遮罩 | `138****5678` |
| 身份证 | 中间遮罩 | `110***********1234` |
| 银行卡 | 只显示后4位 | `****1234` |
| 邮箱 | 遮罩用户名 | `t***@example.com` |

## 5. 重试与降级

### 重试策略

| 场景 | 重试次数 | 间隔 |
|------|---------|------|
| 第三方 API 超时 | 3次 | 指数退避（1s/2s/4s） |
| 数据库连接失败 | 3次 | 固定 1s |
| 消息发送失败 | 5次 | 指数退避 |

### 降级策略

| 场景 | 降级方案 |
|------|---------|
| 缓存不可用 | 直接查库 |
| 第三方服务不可用 | 返回默认值 / 缓存数据 |
| 搜索服务不可用 | 降级为数据库 LIKE 查询 |
