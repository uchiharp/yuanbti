# Spike 报告模板参考

> 此文件是 Spike 报告的参考模板，供 tech-spike 阶段使用。
> 实际 Spike 报告写入 `$PROJECT_DIR/SPIKE-REPORT.md`，使用 `templates/spike-report.md` 格式。

## Spike 报告结构

### 必须包含的章节

1. **验证概要** — 项目名、日期、时间投入、验证点数量
2. **每个风险点** — 验证目标、成功标准、验证方法、代码片段、验证结果、新发现风险
3. **总结** — 通过/不通过/有条件通过的统计
4. **结论路由** — 下一步行动

### 验证目标定义

每个 Spike 必须明确回答：
- 要证明什么？（技术可行性/性能/安全性/集成性）
- 怎样算通过？（具体的成功标准）
- 怎么验证？（最小原型/压测/集成测试）

### 成功标准示例

| Spike 类型 | 成功标准示例 |
|-----------|------------|
| API 兼容性 | 调用成功，响应格式符合预期，错误处理正确 |
| 性能验证 | 1000 QPS 下 P95 < 200ms，无 OOM |
| 框架可行性 | 核心功能 Demo 可运行，API 覆盖需求 |
| 数据库方案 | 复杂查询 < 100ms，索引命中率 > 90% |
| 安全方案 | 认证流程完整，Token 刷新正确，权限隔离有效 |

### 代码片段要求

- 只放关键代码（验证逻辑），不放完整实现
- 包含注释说明验证点
- 包含运行结果/日志输出

### 结论格式

每个风险点必须给出明确结论：

```
结论：✅ 通过
详情：{具体分析}

结论：❌ 不通过
详情：{失败原因}
建议：{调整方案}

结论：⚠️ 有条件通过
条件：{需要满足的条件}
详情：{具体分析}
```

### 时间管理

| 阶段 | 时间占比 | 说明 |
|------|---------|------|
| 准备 | 15min | 明确目标、定义标准、准备环境 |
| 执行 | 2-3h | 搭建原型、执行验证、记录数据 |
| 总结 | 30min | 整理结论、评估风险、写报告 |

**总时间上限：4小时**。超时视为不通过。

### 常见 Spike 场景

#### 1. 第三方 API 集成验证
```bash
# 最小验证
curl -X POST https://api.example.com/v1/action \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"key":"value"}'

# 记录：响应时间、响应格式、错误处理
```

#### 2. 数据库性能验证
```sql
-- 创建测试数据
INSERT INTO orders SELECT ... FROM generate_series(1, 1000000);

-- 执行计划分析
EXPLAIN ANALYZE SELECT * FROM orders WHERE user_id = ? AND status = ?;

-- 记录：执行时间、索引使用、行扫描数
```

#### 3. 框架特性验证
```javascript
// 最小 Demo
const app = require('framework');
app.get('/test', (req, res) => {
  // 验证核心特性
  res.json({ status: 'ok' });
});
app.listen(3000);

// 记录：启动时间、内存占用、API 响应
```

### Spike 报告质量检查

- [ ] 每个风险点有明确结论
- [ ] 成功标准在验证前定义（不是事后凑）
- [ ] 代码片段可运行（不是伪代码）
- [ ] 包含实际运行结果/日志
- [ ] 新发现的风险已记录
- [ ] 总时间在 4 小时内
- [ ] 结论路由明确（通过/不通过/有条件通过）
