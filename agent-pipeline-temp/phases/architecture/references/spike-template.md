# Spike 报告模板

执行者应按以下格式产出报告：

```markdown
# SPIKE-REPORT.md

## Spike 1: {技术点名称}

### 验证目标
{具体要验证什么，一句话}

### 验证过程
{做了什么实验、写了什么原型、调用了什么API、遇到了什么问题}

### 结论
- ✅ 可行 / 🟡 部分成功（需调整）/ ❌ 不可行

### 原型代码
→ {路径}

### 建议
{对后续阶段的影响、需要注意的事项}

---

## Spike 2: {技术点名称}

### 验证目标
{具体要验证什么，一句话}

### 验证过程
{做了什么实验、写了什么原型、调用了什么API、遇到了什么问题}

### 结论
- ✅ 可行 / 🟡 部分成功（需调整）/ ❌ 不可行

### 原型代码
→ {路径}

### 建议
{对后续阶段的影响、需要注意的事项}

---

## 总结

| Spike | 结论 | 影响 |
|-------|------|------|
| Spike 1 | ✅/🟡/❌ | {影响} |
| Spike 2 | ✅/🟡/❌ | {影响} |

### 整体决策
- [ ] 全部通过 → 继续后续阶段
- [ ] 部分不通过 → 调整架构方案
- [ ] 全部不通过 → 重新设计

### 发现的新风险
- {新风险 1}
- {新风险 2}
```

## 部分成功报告格式

当结论为 🟡 部分成功时，必须包含：

```
部分成功：
- ✅ 可用：[列出具体可用功能]
- ❌ 不可用：[列出具体限制]
- ⚠️ 变通方案：[如何绕过限制]
- 📊 可行度评估：XX%
```

## 验收标准

- [ ] 验证目标明确（一句话能说清要验证什么）
- [ ] 验证过程具体（描述了具体实验步骤，不是"测试了一下"）
- [ ] 结论清晰（✅/🟡/❌ 三选一，不含糊）
- [ ] 部分成功时有限制清单和变通方案
- [ ] 原型代码可运行
- [ ] 行数 ≥ 30行
